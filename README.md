# tg_bot — бот с расписанием пар

Telegram-бот, который хранит расписание занятий и присылает его в личку
и в учебные группы. Умеет работать с расписанием «чётная / нечётная неделя»,
загружать пары из таблицы Excel, каждое утро присылать в группу расписание
на день, а заодно показывать погоду и котиков.

Бот: [@schedule_pairs_bot](https://t.me/schedule_pairs_bot)

## Возможности

- **Расписание на 7 или 14 дней.** Для двухнедельного бот сам считает,
  какая неделя идёт сейчас, — достаточно один раз ответить «сейчас 1-я»
  или «сейчас 2-я». Если неделя сбилась — `/switch_week`.
- **Загрузка из Excel.** Бот присылает шаблон, его заполняют и отправляют
  обратно. Каждая строка проверяется, при ошибках бот называет номер строки
  и ничего не сохраняет.
- **Что сейчас.** `/now` — какая пара идёт и сколько до конца, какая
  следующая и через сколько начнётся.
- **Часовой пояс по городу.** Всё время считается по местному времени
  расписания (город → пояс через геокодер).
- **Группы.** Расписание привязывается к одной или нескольким группам,
  там работают `/today`, `/week`, `/now`. Каждое утро в 7:00 по местному
  времени бот присылает в группу пары на день.
- **Погода и котики.** `/weather Омск`, `/cat`.

## Как пользоваться

1. Напиши боту в личку `/new`.
2. Ответь на вопросы: название, город, 7 или 14 дней, какая сейчас неделя.
3. Бот пришлёт шаблон `raspisanie.xlsx` — заполни его и отправь обратно.
4. Готово: `/today`, `/tomorrow`, `/week`, `/now`.

Чтобы расписание было в группе:

1. Добавь бота в группу и отправь там `/group` — бот покажет id группы.
2. В личке с ботом: `/bind <id группы>`. Привязать может только
   администратор группы.

## Команды

### В личке

| Команда | Что делает |
|---|---|
| `/start`, `/help` | приветствие и справка |
| `/new` | создать расписание (одно на пользователя) |
| `/template` | шаблон Excel — с текущими парами или с примерами |
| `/now` | какая пара сейчас и какая следующая |
| `/today`, `/tomorrow`, `/week` | расписание на день или неделю |
| `/switch_week` | поменять местами 1-ю и 2-ю неделю |
| `/timezone <город>` | показать или поменять часовой пояс |
| `/bind <id>`, `/unbind` | привязать или отвязать группу |
| `/delete` | удалить расписание (с подтверждением) |
| `/weather <город>`, `/cat` | погода и котик |
| `/cancel` | отменить текущий диалог |

### В группе

`/start`, `/help`, `/now`, `/today`, `/tomorrow`, `/week`, `/group`,
`/weather`, `/cat`.

## Формат таблицы

Одна строка — одно занятие.

| День | Начало | Конец | Предмет | Кабинет | Преподаватель | Неделя |
|---|---|---|---|---|---|---|
| Пн | 08:30 | 10:00 | Матанализ | 305 | Иванов И.И. | каждая |
| Пн | 10:10 | 11:40 | Физика | 112 | | 1 |

- **День** — `Пн`…`Вс` или полное название.
- **Начало / Конец** — `ЧЧ:ММ`, конец позже начала.
- **Кабинет, Преподаватель** — необязательные.
- **Неделя** — `каждая`, `1` или `2` (пусто = каждая). Для расписания
  на 7 дней колонка не учитывается.

Новый файл полностью заменяет занятия расписания.

### Как считается неделя

Бот хранит номер недели, который назвал пользователь, и понедельник той
недели. Для любой даты считается, сколько недель прошло от этого
понедельника: чётное число — та же неделя, нечётное — другая.
`/switch_week` просто перезаписывает эту точку отсчёта.

## Стек

- Python 3.12, [uv](https://docs.astral.sh/uv/)
- [aiogram 3](https://docs.aiogram.dev/) — бот, FSM для диалогов
- SQLAlchemy 2.0 (async) + asyncpg, PostgreSQL 17, Alembic
- pydantic-settings — конфиг из `.env`
- pandas + openpyxl — шаблон и разбор Excel
- aiohttp — [Open-Meteo](https://open-meteo.com/) (погода и геокодер)
  и [TheCatAPI](https://thecatapi.com/), ключи не нужны
- APScheduler — утренняя рассылка
- Docker, Docker Compose; ruff — линтер и форматтер

## Структура проекта

```
src/tg_bot/
├── main.py           сборка бота: роутеры, middleware, запуск и остановка
├── core/             настройки, подключение к БД, константы и тексты, исключения
├── models/           модели SQLAlchemy: User, Schedule, Lesson, Chat
├── crud/             запросы к БД (CRUDBase и наследники)
├── handlers/         роутеры с командами, FSM-состояния, кнопки, валидаторы
├── middlewares/      сессия БД и перехват ошибок валидации
└── services/         Excel, расчёт недели, вывод расписания, погода, котики,
                      утренняя рассылка
migrations/           миграции Alembic
```

### Как обрабатывается сообщение

```
update → ValidationErrorMiddleware → GetSessionMiddleware → хендлер
                                                              ├─ validators
                                                              ├─ crud
                                                              └─ services
```

- Хендлер не пишет SQL и не ходит в API сам — только вызывает `crud`
  и `services`.
- Проверки вынесены в `handlers/validators.py`: валидатор возвращает
  проверенное значение или поднимает `BotValidationError` с текстом для
  пользователя. `ValidationErrorMiddleware` отправляет этот текст
  и прерывает обработку, а `GetSessionMiddleware` откатывает транзакцию.
- Все тексты и числовые значения — в `core/constants.py`.

### База данных

| Таблица | Что хранит |
|---|---|
| `users` | пользователи (id из Telegram) |
| `schedules` | расписание: владелец (одно на пользователя), 7/14 дней, точка отсчёта недели, часовой пояс |
| `lessons` | занятия: день, время, предмет, кабинет, преподаватель, неделя |
| `chats` | группы, привязанные к расписанию |

## Настройки

Скопируй `.env.example` в `.env` и заполни:

| Переменная | Что это |
|---|---|
| `TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `postgres_user` | пользователь базы |
| `postgres_password` | пароль базы (без символов `@ : / ? #`) |
| `postgres_db` | имя базы |
| `postgres_server` | адрес базы (`localhost` для локального запуска) |
| `postgres_port` | порт базы (`5432`) |

`.env` в git не хранится.

## Запуск в Docker

```bash
docker compose up -d --build
```

Поднимаются два контейнера:

- `db` — PostgreSQL 17. Пользователь и база создаются при **первом**
  запуске из `postgres_user`, `postgres_password`, `postgres_db`
  (потом их смена в `.env` на базу не влияет). Данные хранятся в томе
  `pgdata` и переживают перезапуск. Порт наружу не открыт.
- `bot` — ждёт готовности базы, применяет миграции и запускается.
  `postgres_server` и `postgres_port` из `.env` здесь не используются —
  внутри Docker база доступна по имени сервиса `db`.

Полезные команды:

| Команда | Что делает |
|---|---|
| `docker compose ps` | статус контейнеров |
| `docker compose logs -f bot` | логи бота |
| `docker compose restart bot` | перезапуск бота |
| `docker compose down` | остановить всё (данные сохранятся) |

`docker compose down -v` удалит том с базой — все данные пропадут.

### Обновление на сервере

```bash
git pull && docker compose up -d --build
```

Пересобирается только бот, база не трогается, новые миграции применяются
при старте.

## Локальный запуск

Нужны запущенный PostgreSQL и uv.

```bash
uv sync
uv run alembic upgrade head
uv run tg-bot
```

Нельзя одновременно запускать две копии бота с одним токеном: Telegram
отдаёт обновления только одной (`TelegramConflictError`). Для разработки
удобно завести отдельного тестового бота.

## Разработка

```bash
uv run ruff check
uv run ruff format
```

Миграции после изменения моделей:

```bash
uv run alembic revision --autogenerate -m "описание"
uv run alembic upgrade head
```

Новую модель нужно импортировать в `models/__init__.py`, иначе Alembic её
не увидит. Сгенерированную миграцию стоит просмотреть перед применением.
